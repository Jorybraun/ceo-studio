# PIPE-OS Canonical Brief Template

Use this template for every PIPE-OS task brief. Keep it current with the rendered UI and the board state so the task does not drift.

### Next Action

### Owner / Persona
- Owner: [person name or role]
- Persona: [kanban-orchestrator | pipe | researcher | designer | other]

## How to use this template
- Fill in every field before moving a task into execution.
- Keep the “Current Rendered State” grounded in what is actually visible, not what is assumed.
- Write the “Problem / Mismatch” as a delta between intent and reality, not as a general complaint.
- Make acceptance criteria testable and observable so another agent can verify them.
- Update the board, domain, and owner/persona whenever responsibility changes.
- If the rendered UI changes, revise the brief immediately to prevent documentation drift.
